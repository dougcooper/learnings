The brief. Signal's Double Ratchet is great, but it is purely classical — vulnerable to a future quantum adversary doing "Harvest Now, Decrypt Later." Apple's PQ3 adds a post-quantum layer on top of Kyber, but only amortizes it every ~50 messages. This paper fixes both problems: better amortization and a smaller lattice KEM called Katana.

The paper introduces the Triple Ratchet (TR): a hybrid-secure messaging protocol that pairs Signal's classical Double Ratchet with a post-quantum ratchet that uses erasure codes to amortize large ciphertexts chunk-by-chunk. The post-quantum ratchet is built from a new lattice-based ratcheting KEM called Katana, which halves Kyber's per-epoch bandwidth while fixing a critical security flaw in prior lattice-based ratchet proofs using the hint-MLWE assumption.

Why a Triple Ratchet?

Signal/WhatsApp/Messages are all built on the Double Ratchet. The Double Ratchet is only secure under classical DH assumptions — Shor's algorithm breaks it. Today's transcripts can be stored and decrypted later.

Existing defenses

PQXDH & PQ3

PQXDH (2023) protects only the initial handshake. PQ3 (Apple, 2024) protects the whole session by adding a Kyber-768 ratchet to the Double Ratchet.

The catch. Kyber-768 pk+ct is 2,272 bytes per epoch — ~71× larger than a single DH group element. PQ3 amortizes this by re-sending only every ~50 messages, but in unbalanced conversations (typing indicators, offline laptops, linked devices) the amortization fails and the same 2,272-byte blob is repeated message after message.
The TR fix

Two independent improvements

1. Split the long PQ message with an erasure code: send one fresh chunk every message, decode after any 50 chunks. Cost is now balanced — no amortize-or-explode.

2. Replace Kyber with Katana: a Kyber-style RKEM where Bob's "ciphertext" doubles as his "public key" (Signal-style reuse), saving a factor of 2 — but proven secure only via the new hint-MLWE assumption.

Triple Ratchet Architecture

Three ratchets run in parallel, each producing a key stream. The message key is the XOR of the classical and post-quantum key streams. The two CKAs evolve at their own pace.

Why two roots? In PQ3, the classical and post-quantum ratchets are synchronized and share one root key. With erasure-coded chunks, the PQ ratchet can "fall behind" the classical one — so TR keeps two separate roots and combines their message-key streams. The sender also tracks how many chunks the receiver has acknowledged before committing the updated PQ root to message-key derivation.

Katana — Lattice RKEM

A ratcheting KEM whose ciphertext doubles as the next public key — the lattice analogue of Signal's "send gb as ciphertext+next-pubkey" trick. Built on the LPR/LP KEM underlying ML-KEM (Kyber), but with one fewer element transmitted per epoch.

The trick

Reuse Bob's ciphertext as his next public key

Classical DH: Alice has ga, Bob sends gb. Shared secret: gab. Bob's gb is both the KEM ciphertext and Alice's next public key — one element does two jobs.

Katana does the same with MLWE: Bob's uB = D·sB + eB serves as both the encapsulation (decoded to a seed via rounding) and Alice's public key for the next round.

The Security Flaw They Found

Prior lattice-based RKEMs [ACD19, LKS23] claimed a DDH-style security proof for the "ciphertext = next public key" trick. The proof is subtly wrong — and the error is fundamental, not just a tunable parameter.

The flaw (Item L.1). In the DH setting, the simulator can produce gab given only Alice's ga and a random oracle. The lattice analogue fails: the "shared" component vA algebraically contains an expression involving Bob's secret sB that cannot be simulated from Alice's secret sA alone. A compromised Alice's secret leaks a statistical bias on Bob's secret, which then biases the next round — a vicious cycle.
Why it matters
The reduction needs to embed a DDH challenge into the protocol. If you can't simulate the "shared secret" part without the peer's secret, you can't embed anything — and PCS is not actually reduced to MLWE.
Why prior work missed it
[ACD19, LKS23] each invoked an analogue of the DH Item (C.2) without checking that Item (C.1)/Item (L.1) holds. In DH the symmetry hides the issue; in lattices it doesn't.
The fix: hint-MLWE. Rather than noise-flooding (which makes parameters unusable), Katana proves Item (L.1) computationally using the hint-MLWE assumption [KLSS23, EEN'24]: MLWE stays hard even given some noisy linear leakage of the secret. With hint-MLWE in hand, Item (L.2) goes through and the full reduction to MLWE is restored.

Katana — Core Algorithms

Simplified (no bit-dropping). The full scheme has two modes — fresh key generation and "updated" key generation — and four algorithms total.

Open Questions & Production Outlook

Status

Active Signal evaluation

Authors are in discussion with the Signal team; Signal is actively evaluating a variant of TR for a future protocol iteration. Apple has not yet committed.

Caveats

Known trade-offs

  • Two roots, two ratchets. More state per session than PQ3.
  • hint-MLWE is newer than MLWE. Cryptanalysis is reduced from MLWE, but the reduction is not tight — parameter set is conservative.
  • Trades constant overhead for worst-case. Balanced conversation: TR slightly heavier per epoch than PQ3 (1,416 × 50 vs amortized 2,272 + cheap msgs). Worst case is the win.
  • Signature overhead excluded from comparison. PQ3's 64 B signature was stripped for an apples-to-apples view.
